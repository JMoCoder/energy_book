## 规范工作流（三步闭环，防错减Bug）

### 第一步：自动生成零缺陷 HTML 脚手架

在撰写前，首先在终端运行脚手架生成脚本（将 `XX_X_X` 替换为实际章节 ID）：

```bash
python3 scripts/create_chapter.py XX_X_X
```

该脚本会自动：

1. 从 `data/toc.json` 检索章节标题、LEVEL、所属章及前后相邻章节。
2. 自动生成标准 HTML 文件到 `chapters/level_XX/` 目录下。
3. 预先内嵌全套 DOM 结构（顶部导航、页眉、学习目标、场景引入、正文容器、小结、**带 `checkAnswers()` 提交按钮与得分展示的 `quiz-section` 测验区**、**底部导航 `bottom-nav`**、**`cross-refs` 相关章节**、页脚、返回顶端按钮）。
4. 确保绝对不会发生 DOM 顺序错乱、遗漏按钮或类名拼错等低级 Bug。

---

### 第二步：高质量填充正文内容

直接编辑已生成的 HTML 文件，严格按以下质量标准填充内容：

#### 1. 场景引入 (200-400 字)

- **禁止**"本节将学习……"或"定义轰炸"式开头。
- **必须**用一个具体的、有代入感的**工程场景 / 突发告警 / 现实问题**切入，让读者在读完引入后自然产生"那背后的原理是什么"的疑问，再顺势展开正文。

#### 2. 核心正文 (5,000–10,000 字，以讲透为准)

每引入一个新概念，必须严格执行**三层递进**：

| 层次 | 任务 | 关键要求 |
|------|------|----------|
| **第一层：直觉感受** | 用一句大白话说清楚"这是什么" | 零专业词汇，任何人都能秒懂 |
| **第二层：生活类比** | 用可感知的日常场景类比解释物理机制 | 类比必须**完整闭环**：类比里的每个元素都要对应回电路概念，不能停留在表面 |
| **第三层：工程意义** | 解释它在储能系统里具体有什么作用 | 优先使用中国真实项目 / 政策（精确到 MW 数、文号或年份） |

**字数自查标准**：一个完全没有电气背景的读者，读完这节，能不能独立向别人解释核心概念？如果能——字数够了；如果不能——说明还没讲透，继续写。

**禁止行为清单**：
- ❌ 没有铺垫直接抛公式或专业术语
- ❌ 一段话内连续引入三个以上未解释的新概念
- ❌ 提到概念后只用一两句带过（浅尝辄止）
- ❌ 类比只是表面类比，没有将每个对应元素逐一解释清楚
- ❌ 专业缩写首次出现未附中英文全称（格式：`储能变流器（Power Conversion System，PCS）`，后文可直接用"PCS"）
- ❌ 为每个物理量都单独列定义式，或堆砌同一关系的多种变形公式（增加学习负担，无助于理解）
- ❌ 公式孤立出现，前后无文字铺垫与工程含义说明
- ❌ 用公式取代本可用文字和类比讲清楚的概念（公式不是"显示深度"的工具）

**公式使用原则（铁律六）——非必要不引入**：

写作篇幅的重心在于概念的**多方位解析**（直觉感受 → 生活类比 → 物理行为 → 工程意义），公式只是最后的精确标注，**不是必选项**。**同时满足以下条件才引入公式**：
1. 该关系用文字和类比无法准确、完整地表达；**且**
2. 缺了它读者无法建立正确的数量级直觉，或工程实践中需用其做估算/取舍判断

**能用一句话描述关系的，不用公式；能用数量级感受替代的，不用公式；纯粹为了"看起来严谨"的，绝对不用公式。**

**公式密度参考上限**：概念科普类章节（LEVEL 1–2）全节 ≤ 2 个；原理分析类（LEVEL 3–5）全节 ≤ 4 个；技术计算类（LEVEL 6–8）按实际需要，但每个公式后必须紧跟工程含义说明。

子模块划分：根据实际内容需要，灵活划分 2–6 个 H2 子模块，不强制"2-4个"。

#### 3. 六种边栏组件规范

| 用途 | 类名 | 图标 |
|------|------|------|
| 关键要点 / 记忆技巧 | `callout callout-tips` | 💡 |
| 常见误区 / 安全提示 | `callout callout-warning` | ⚠️ |
| 中国真实案例 | `callout callout-case` | 🏗️ |
| 生活类比（每个新概念必须有） | `callout callout-analogy` | 🔍 |
| 深入探索方向 | `callout callout-extension` | 🔭 |
| 重要定义 / 公式 | `key-concept` | 📌 |

#### 4. 知识测验 (5 道单选题)

- ✅ 题目**以检验概念理解与辨析为核心**，例如：
  - "以下哪种说法正确描述了X的本质？"
  - "当Y发生时，会导致什么物理现象/政策后果？"
  - "以下关于Z的叙述，哪一项是错误的？"
  - "机制A与机制B的根本区别在于哪里？"
- ❌ **严禁出数值计算题**（如"求某电路电流值""计算该功率因数"等需要代入数字运算的题目）。
  - **唯一例外**：若本节章节本身就是在讲解某一完整计算流程（如"峰谷套利窗口计算""调频里程收益公式推导"等），则允许出1道与该计算流程直接相关的应用题，但必须是对计算逻辑的理解与辨析，不得是纯粹的数字代入。
- 每题须包含题干、ABCD 选项、`<div class="quiz-answer">` 及 100-150 字深度解析（解析须说明**为何其他三个选项是错的**）。
- **保留脚手架自带的 `<button class="btn-check-answer" onclick="checkAnswers()">查看答案与解析</button>` 和 `<p class="quiz-score" id="score-display"></p>`**，勿误删！

### 第三步：自动校验与一键提交发布

正文填充完成后，在终端运行自动校验与发布脚本：

```bash
python3 scripts/publish_chapter.py XX_X_X
```

该脚本会自动闭环执行：

1. **自动门禁校验**：调用 `validate_chapter.py`，检测 DOM 顺序、测验按钮、类名规范与资源引用，未通过将自动拦截阻止发布并报错提示。
2. **数据同步**：将 `data/toc.json` 中的状态更新为 `available`，并同步更新 `index.html` 的离线 TOC。
3. **远程推送**：自动执行 Git add/commit/push，部署至 GitHub Pages。
